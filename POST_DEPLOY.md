# POST_DEPLOY — creative-tester

Run these once after `make deploy`. The stack ships with the pacer/poller schedules
**disabled** so nothing submits until you've populated secrets and smoke-tested.

## 1. Deploy

```
make deploy STACK=creative-tester-dev            # first time: sam build && sam deploy --guided
```
Note the `ApiBaseUrl` output — call it `$API`.

## 2. Populate secrets

`callback-secret` is auto-generated by CloudFormation. You only set the classifier key:

```
aws secretsmanager put-secret-value \
  --secret-id creative-tester-dev/classifier-dev-api-key \
  --secret-string 'PASTE_THE_DEV_X_API_KEY'
```

## 3. Smoke test (schedules still off — drive the Lambdas by hand)

```
# create a 2-URL batch (one video, one image)
curl -s -XPOST $API/jobs -H 'content-type: application/json' -d '{
  "urls": "https://media-cdn.example.com/a.mp4, https://static.example.com/b.jpg"
}'
# -> {"job_id":"job_...","enqueued_rows":2,"skipped":[]}

aws lambda invoke --function-name creative-tester-dev-pacer /dev/stdout   # submit ~1/18s
# repeat a few times, ~20s apart, until GET below shows rows 'submitted'

curl -s $API/jobs/JOB_ID            # status + counts
curl -s $API/jobs/JOB_ID/results    # per-row raw_result + norm_tags

aws lambda invoke --function-name creative-tester-dev-poller /dev/stdout   # pull results / mark stalls
```

## 4. Verify the callback parameter name (the one open unknown)

The dev classifier's webhook field name is unconfirmed. With `CALLBACK_PARAM=callback_url`
(default), submit one asset and watch whether the `callback` Lambda logs a delivery:

```
aws logs tail /aws/lambda/creative-tester-dev-callback --follow
```

- **Callback arrives** → done; push path works.
- **No callback within a few minutes** (but the poller still completes the row) → the
  field name is different. Redeploy with the right name and re-test:
  ```
  make deploy STACK=creative-tester-dev \
    ARGS='--parameter-overrides Stage=dev CallbackParam=webhook_url'
  ```
  (or confirm the field with whoever owns the dev classifier). The service stays correct
  either way because the poller is the fallback — this only makes results arrive faster.

## 5. Turn on the schedules

Once the smoke test passes, enable continuous operation. Either flip `Enabled: true` on
the pacer `Tick` and poller `Sweep` events in `template.yaml` and redeploy, or
enable the generated EventBridge rules directly:

```
aws events list-rules --name-prefix creative-tester-dev      # find the rule names
aws events enable-rule --name <PacerTickRule>
aws events enable-rule --name <PollerSweepRule>
```

## 6. Comparison (optional)

```
curl -s -XPOST $API/compare -H 'content-type: application/json' -d '{
  "left":  {"job_id":"JOB_ID","endpoint":"dev-video","url":"https://.../a.mp4"},
  "right": {"job_id":"JOB_ID","endpoint":"dev-image","url":"https://.../a.mp4"}
}'
curl -s $API/comparisons/CMP_ID
```

## Notes / gotchas

- The pacer has **reserved concurrency 1** — the account needs at least 2 of unreserved
  concurrency headroom or the deploy fails.
- Rate limiting is **global per classifier** via the `RATE#dev` record, so multiple
  concurrent batches still share one 18s gap — safe by design.
- TTL removes every job/result/comparison 30 days after creation automatically.
